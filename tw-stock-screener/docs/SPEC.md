## 2. 使用者先前明示的第一階段基線

專案名稱為 `tw-stock-screener`，使用 Python，針對台灣上市、上櫃普通股每日選股。第一階段完成資料取得、KD 計算、選股核心與測試，暫不開發網頁報表。

### 選股條件

1. 使用 TWSE、TPEx 官方行情來源，排除 ETF、權證等非普通股。
2. 合併上市、上櫃，依指定交易日漲跌幅百分比由高到低，取前 300 名。
3. 依序篩選：日 KD（26,3,3）K > D、週 KD（26,3,3）K > D、月 KD（26,3,3）K > D、當日成交量／前一交易日成交量 ≥ 3.2。
4. 不增加最低成交量限制。
5. KD 使用未還原 OHLC；週、月包含選股日所在的未完成 K 棒。
6. RSV 使用 26 期，K、D 採遞迴平滑；先前要求建議初始 K、D 為 50，並保留足夠暖機歷史。
7. 支援指定歷史交易日，禁止使用該日之後行情參與選股。
8. 資料缺漏、前日成交量為零或 API 失敗不可誤判通過。

### 程式與交付

- 模組化設計，資料來源與快取分離，參數集中於 YAML。
- 歷史 OHLCV 使用本地快取，支援增量更新。
- CLI 支援最新交易日及指定日期。
- JSON、CSV 包含股票代號、名稱、漲幅、成交量、量比與日週月 K/D。
- 保留各階段篩選數量與錯誤紀錄。
- 提供單元測試、KD 計算驗證工具、README、安裝與執行方式、測試結果及未解決問題。
- 先驗證官方資料來源的可用性、歷史查詢、欄位及限制；不得假設 API 永遠可用，不得以模擬行情冒充實際結果。限制與替代方案須說明，不得自行改動選股規則。

使用者後續要求修改為需要資料時才取得；現有程式已採按需下載。這是資料取得方式的修改，不授權變更選股條件。

### 結果版本與追蹤的本機行為

- 計算完成不等於正式發布。每次 screen 新增不可由一般介面改寫的結果版本，再匯出原有 JSON／CSV；不自動切換正式版。
- 使用者已於2026-10-10確認：每次選股（含首次及重算）先保存待確認版本，經使用者確認才成為正式結果；不自動正式化、不覆蓋舊版。
- approve 指定新版本與已檢視的現行正式版本。版本已變更則拒絕，避免並行誤覆蓋。舊結果及確認事件保留。
- 版本含設定、規則摘要雜湊及本次成功取得的計算輸入雜湊；這不等於已封存每個版本的完整 OHLC 快照，完整資料修訂重播仍待整合。
- 有個股錯誤的結果可保留為待確認版；確認前須檢查並明確承認錯誤。整體失敗不能建立成功結果版本。
- 追蹤只比較該日及報告明示的前一交易日正式版本。缺前日正式版標示 insufficient_history；任一版含錯誤標示 incomplete_data；規則雜湊缺少或不同標示 incompatible_rules；均不產生新增／退出訊號。
- 使用市場與代號識別股票。連續入選沿正式報告的前一交易日回溯；遇缺結果、錯誤或規則不同只提供已確認連續天數下限；遇已知未入選才確定連續天數。
- 追蹤在查詢時重新計算；舊正式版本修訂後，後續查詢不沿用過期追蹤結果。回應保留比較及連續計算所用版本識別。
